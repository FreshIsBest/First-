## Instructions for the AI

Follow this order exactly. It is built so the owner sees a real result early (their brand, then their store) and the invisible automation gets built last, once the pieces it runs already work. Two things never bend, whatever the order: nothing risky (publish, send, spend) happens without the owner's click, and the spend cap is set before the first tool that could cost money. Both are covered in `03-build-order.md`, which is the detailed step-by-step for everything below.

**Step 0: Load the rules.** Read `CLAUDE.md` in this folder and obey it for the entire build. The most important rule: **make it work before you make it look good, and let the owner see a real result early.** If the owner asks to polish the system itself before it runs, give them your honest advice once, then respect their call (see the vanity-trap rule).

**Step 0b: Get the owner set up (before the interview).** The owner has read only `READ-ME-FIRST.txt` and is talking to you in the Claude Code app. Read `SETUP.md`; it is your guide for this, not theirs. The short version: keep them in the app for now (it is perfect for the interview and the early build), tell them up front that you will move them to a free app called VS Code later, when the build reaches the automation and needs a terminal, and that you will walk them through it then. Do not make a beginner install anything before they have seen a real result. Set the escape-hatch expectation now too: if they ever see an error, they paste the whole thing to you and you fix it. Then begin the interview.

**Step 1: Interview the owner.** Open `01-interview.md` and run it. Ask one topic at a time, wait for answers, do not assume. Write everything into `PROFILE.md` in the owner's project; it drives every later decision. When the interview closes, seed the memory vault: `PROFILE.md` is the system's first note, so create a `memory/` folder for it and optionally point the owner at Obsidian so they can see what their system knows from day one. Empty vault only here; the full layer gets built at Step 4, with the tools.

**Step 2: Choose where it runs.** Read `05-infrastructure.md`. Settle local vs VPS from the owner's computer and runtime answers: a decent machine that stays on runs locally (simplest, cheapest), a weak machine or a real 24/7 need takes the VPS path. Set it up before you build. Quick routing decision, not a detour.

**Step 3: Build their brand (the first real win).** Open `modules/brand-kit.md`. Build the owner a brand from scratch: shop-name options, a logo, a color palette, a brand-voice guide, all as drafts they approve. This is deliberately first so the owner sees something real in the first sitting, and it is safe (a name and a logo publish nothing and spend nothing). Their approving these drafts is the approval habit everything later depends on. This is `03-build-order.md` Step 1.

**Step 4: Connect the tools, set the spend cap, and stand up memory.** Three foundations together. Wire and prove every tool with one real call: the Etsy connection, the image/video engine (Higgsfield), a print-on-demand link if they sell POD; key each in `.env`, never printed (`tools/tools.md` has the how, read `08-gotchas.md` first). **Set the owner's spend cap in code here, before any tool that could spend money is used.** And build the memory vault (`modules/memory.md`), loading the brand voice and preferences into it so the crew you build next reads them and stays on-brand from its first run. This is `03-build-order.md` Step 2.

**Step 5: Build the crew.** Build the five to eight agents from `PROFILE.md` using `04-first-agent.md` as the template: tight prompt, only the tools that job needs, reads the memory vault for voice, produces a draft the owner approves, never acts on its own. Run them by hand for now (no automation yet, so a human is always in front of everything). This is `03-build-order.md` Step 3.

**Step 6: Build the first real listing.** Have the crew produce one complete listing end to end: image, title, description in the owner's voice, tags, price, all as a draft. The owner reviews the real thing and approves it by hand. This proves the whole chain (brand, tools, memory, crew) works on one real product before you scale. Always preview the real artifact, never a summary (`08-gotchas.md`). This is `03-build-order.md` Step 4.

**Step 7: Scale the store and go live.** Open `modules/etsy-store-builder.md`. The crew builds out the full store from the brand kit: shop identity, a starter product line, the rest of the listings, launch content, all as drafts under one review. The owner approves and opens the shop (the store-builder has the full account walkthrough: seller account, getting paid, paying Etsy's fees). Read the compliance section at the end of `08-gotchas.md` before anything publishes, and lean on `07-approval-loops.md` for the deeper board. This is `03-build-order.md` Step 5.

**Step 8: Build the system (the automation).** Now, and not before, build the engine that runs it all unattended, from `02-architecture.md`: the task queue, the dispatcher loop, and the real approval board. Until now the owner ran agents by hand and approved in person, which is why it was always safe. This step makes it run on a schedule, with risky tasks still waiting on the board. Harden the full spend caps here too (`06-cost-and-billing.md`) and fold the ongoing lessons into the memory vault. You build it now because the pieces it runs already exist and work. This is `03-build-order.md` Step 6.

**Step 9: Only now, make it look good.** Once it earns and runs on its own, help the owner polish: a real approval dashboard (`07-approval-loops.md`), a theme, a name. If the owner wants the signature payoff, `modules/signature-dashboard.md` turns the board into a walkable 3D world (four finished worlds come with their purchase as a separate Worlds Pack download; that module walks them through getting it), which doubles as filmable content for the feed. It is looks, so it belongs here at the end, never earlier. After the first win, `09-after-first-win.md` covers what is next: a second money-maker, scale, or stop. This is `03-build-order.md` Step 7.

## The one rule that matters most
Most people fail because the payoff is buried behind invisible setup and they quit before they see anything real. This order fixes that: brand first, store soon after, automation last. Give the owner a real win early, keep safety on the whole time, and build the automation once the pieces work. Every time.

Start with Step 0.
